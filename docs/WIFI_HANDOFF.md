# v1.2.2：Wi-Fi 交接启动时序测试包

适用于 iPhone 14 Pro Max / iOS 16.2 / Dopamine rootless。版本 1.2.2，构建 1006。

用户报告早上 v1.2.0 可以投屏，v1.2.1 停在 Wi-Fi；发送机手动连热点后能打开接收机的 8080 网页，但 CarPlay 仍未建立。三份日志显示蓝牙识别和认证成功、热点配置已发送，接收服务 7000 / 8080 监听正常，连续发送 300 秒 mDNS 公告，没有发现发送机的 CarPlay 控制服务或收到 AirPlay TCP 连接。手动网页访问验证了热点与 HTTP 可达，尚未验证 CarPlay 服务发现与协议交接。

## 本版修改

旧流程启动蓝牙助手后，先固定等待 8 秒，再检查已经写好的硬件就绪文件，之后才启动 AirPlay / Bonjour。该次日志中，热点配置发送里程碑早于 AirPlay 开始监听约 1.46 秒。v1.2.0 同样存在这段等待，因此它是已确认的时序隐患，尚不能证明是 v1.2.1 回归的唯一原因。

现在直接等待硬件就绪或助手退出；助手报告就绪后立即进入接收服务启动，不再额外等待 8 秒。保留原有就绪超时、干净重试和蓝牙恢复逻辑。检查就绪文件前先检查子进程，避免已退出的助手留下文件导致假成功。此改动缩短启动竞争窗口，未修改蓝牙协议、mDNS 内容、热点凭据或配对数据，也不保证服务在所有情况下都早于发送机请求热点信息。

v1.2.1 的网页播放修复和本机／网页触摸交接均保留。

## 验证与实机测试

自动测试用真实子进程和就绪文件验证：就绪后立即返回、助手退出后残留就绪文件被拒绝、未就绪超时、信号退出。测试不操作真实蓝牙。完成 rootless iOS 编译和包校验不等于实机 CarPlay 握手已验证。

1. 停车，停止 CarPlay、关闭网络探测并退出 Showcase，覆盖安装 1.2.2 deb。无需删除现有配对和热点设置。
2. 开启详细日志，确认版本 1.2.2 / 1006，重新开启 Browser Output、网络探测和 CarPlay。接收机保持前台；发送机开启 Wi-Fi 和蓝牙，先按正常 CarPlay 自动连接流程测试。
3. 成功时 `ready sentinel observed` 后应紧接 `bgPrepareNet` 和 7000 监听，不再额外空等 8 秒；随后应有 CarPlay 控制服务发现或 AirPlay 连接、Pairing / CarPlay / Video 进度。开始播放后再验证手机与网页触摸。
4. 若仍卡住，保持当次会话，导出日志中的 app.log、carplay_bt.log、carplay_services.log。下一阶段需检查发送机的 CarPlay 状态及热点上的 mDNS / 控制连接，不把网页可达当作 CarPlay 协议已完成。

当前根因未完全确认，本包用于验证启动时序修正。保留 v1.2.0 作为已报告可用的回退版本；未声称已完成实机回归修复。
