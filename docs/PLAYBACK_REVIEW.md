# v1.2.1：基于 v1.2.0 的播放与触摸复查

基线：`v1.2.0` / `5ede3394096834ee684209916fbf4b9fc8925ea5`，构建 1004。
本地 `main` 已同步到该提交，修复位于 `codex/playback-touch-review`。
本组修复作为 v1.2.1 / 构建 1005 测试包提供，不代表用户手机已升级，也不宣称行驶兼容性已经验证。

## 已复现和修改

- **等待 IDR 时黑屏**：持续收到非关键帧会更新收帧时间，但播放器一直无法开始；原先只在没有新数据时重试 IDR。等待关键帧期间改为有频率上限地重试，静态画面仍保留原策略。模拟测试先在旧代码失败，再在修复后通过；真实 Chrome 服务故意忽略首次 IDR 请求，持续发送非关键帧，验证页面能自行恢复。
- **旧帧遮住正在播放的新视频**：重连保留的 canvas 旧画面原来只由 `playing` 事件隐藏。真实 Chrome 中抑制该事件后，复现时间轴持续前进、旧画面仍盖在视频上的问题。现在首个实际提交帧（旧浏览器使用解码帧计数）也会隐藏旧帧并恢复触摸，不单独依赖媒体事件。这是已验证的软件路径，不能据此证明实车一定发生了事件遗漏。
- **WebSocket 建连悬挂**：HTTP 成功后媒体或控制的升级若一直没有完成，原先没有页面侧超时。增加 8 秒建连超时，随后走既有退避重连；浏览器缓存恢复页面时重新连接。
- **拖动坐标成批到达时被丢弃**：服务端原先按解析时刻间隔 1/120 秒限频，同一次 TCP 读取中的正常多个移动只保留第一个。改为每秒补充 120 个额度、最多积存 12 个的限频方式。按下、松开和取消不受移动限额影响。
- **网页控制端积压**：网页按显示帧合并移动事件，短滑动在松开前补发最后一个移动，保留松手终点。待发控制数据超过 4 KiB 时取消本页手势并重新连接，避免继续堆积；不能把浏览器缓冲量当作整个无线链路的延迟。
- **捕获与手势清理**：失焦、窗口尺寸变化、取消、断开和流切换都会清理待发移动并释放 pointer capture；长按仍发送 hold 维持服务端保护时限。
- **接收机触摸被网页长期占用**：移除“只要网页控制连接存在就丢弃本机触摸”的策略。本机和网页共用加锁的手势入口；网页空闲时不占用输入。另一端发生新的按下时，先取消旧端手势，旧端后续移动／松开不再影响新手势。后台、流重置、断线和原生 IPC 退出仍会释放相应手势。

## 实车录屏的边界

用户反馈：行驶时 14 Pro Max 原生 CarPlay 正常，车机网页画面不动；停车后重新打开网页正常。尚未验证是否仅切到 P 档即可恢复，重新打开网页本身也可能恢复页面或重连。

录屏中收帧计数持续增加，发送队列为零，缓冲较短，播放恢复次数为零。因此不能直接归因于热点不可达、发送机不来帧或严重缓存积压。浏览器帧提交回调的次数也不能证明导航图像内容发生变化。

诊断增加 `videoPaused`、`videoSeeking`、`videoReadyState`、`videoCurrentTime`、`decodedFrames`、`droppedFrames`、`presentedMediaTime`、`browserPresentedFrames`、`lastPresentedAgeMs`、`pauseCount`、`lastPlayError`、`videoError`、`documentVisibility`、`posterVisible`、`displayed`、`controlBufferedBytes` 和 `inputOwner`。

这些字段用于区分媒体被暂停／播放被拒绝、解码未推进、浏览器呈现异常、页面隐藏和触摸归属。当前网页没有车辆档位接口，不能自动判断 P / D，也没有实现或承诺绕过车辆的行驶视频策略。现场配置、主动排障与复制诊断应在停车后进行。

## 验证与待实测

- `test_browser_input.cjs`：移动合并、短滑动、松手终点、取消、失焦、尺寸变化、长按保活、控制积压、页面缓存恢复和建连超时。
- `test_browser_bridge.py`：真实原生 WS 服务、多个移动合包到达、网页空闲时本机可用、双向手势接管、旧手势拒绝、触摸超时、后台与旧流保护。
- `test_browser_live.cjs`：真实 Chrome MSE、首次 IDR 丢失后恢复、playing 事件缺失时移除旧帧、异常时间戳、连续解码和新增诊断字段。
- `test_browser_e2e.cjs`：生产网关／桥接、1080p、HTTP/WS 与 HTTPS/WSS、实际鼠标事件、长按超过 750ms 后仍有效、失焦即时取消、断线和前后台恢复。
- 保留 v1.2.0 的有限卡帧恢复、模拟 30 分钟缓冲清理、网络守护、HTTPS 及 iOS 16.2 / arm64 编译检查。

桌面及模拟测试不能代替 iPhone 的 HID 手感、热点重建、车机视频策略或驾驶场景呈现验收。输入仲裁需要先停车确认手机和网页可交替点击、拖动、长按，且旧端松手不会打断新端手势。
