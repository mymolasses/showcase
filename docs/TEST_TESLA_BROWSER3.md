# Browser3：焕新版 Model Y 实车网络探测

适用：iPhone 14 Pro Max / iOS 16.2 / Dopamine rootless 接收机；另一部 iPhone 发送 CarPlay。
本版增加本地兼容地址与独立 HTTP 探测服务，不需要安卓设备或公网视频中转。
这是实验安装包；自动化未验证 iOS 真机的地址／路由权限，也未验证目标车机固件的 HTTP 策略。

## 安装升级

1. 在 Showcase 三指轻点，点 × 完整停止 CarPlay；若已经启用车机网络探测，先关闭该开关。
2. 下载本次 Release 的 `Showcase-Browser3-iOS16.2-Dopamine-rootless.deb`，交给 Sileo 或 Filza 覆盖安装。
3. 确认 Dopamine 仍处于已越狱状态，打开 Showcase Browser。About 应显示 Browser 3；包版本为 `1.0~beta5-2+browser3`。
4. 测探测页时可以先停止自动连接的 CarPlay 会话，暂不需要连接发送 iPhone。

## 第一步：启动独立探测

1. 在接收机 iOS 设置中开启个人热点，允许其他人加入；让电脑或车机连接此热点，使热点桥接口实际建立。
2. 返回 Showcase → Settings → Display，打开 **Tesla Network Probe / 车机网络探测**。
3. 等待约 2–3 秒，点击 **Refresh Network Status / 刷新探测状态**。
4. 应显示 `local_ready`：仅代表本机已经在回环接口创建 `99.99.99.99/32` 别名，并确认内核本地路由；还不代表实车访问成功。
5. 保持 Showcase 前台。开启探测期间会禁用自动锁屏；本版不承诺后台或锁屏保活。

开关与 Browser Output 独立：探测页不需要 CarPlay、视频解码或四位配对码。

## 第二步：电脑确认兼容入口

电脑连接接收机热点，在浏览器输入完整 URL，按顺序测试：

1. **`http://99.99.99.99/`** —— 标准 HTTP 80 端口探测。
2. **`http://99.99.99.99:8081/`** —— 备用 HTTP 探测端口。
3. 作为对照，打开设置显示的普通热点探测地址，通常为 **`http://172.20.10.1:8081/`**；实际以设置中的地址为准。

页面应显示 **Showcase · 车机网络探测 / Browser3**，随后出现 **双向 HTTP 响应正常**，次数每两秒增加。

若 80 端口被占用，设置不会展示该入口，请直接测试 8081。网页中的“热点回程检查”会尝试确认返回客户端的路由走热点桥；本机回环测试显示未通过是正常的。

## 第三步：停车后实车测试

1. 在焕新版 Model Y 的 Wi-Fi 中选择接收机热点，确认已连接。
2. 特斯拉浏览器先输入 **`http://99.99.99.99/`**，保留 `http://`。
3. 若打不开，再试 **`http://99.99.99.99:8081/`**。
4. 打开后等待 15 秒，确认“双向 HTTP 响应正常”的次数持续增加；这才证明本次实车 HTTP 链路可用。
5. 返回接收机设置，点刷新状态，核对“已收到 HTTP 探测请求”增加。

本版没有实现 HTTPS；如果车机把地址自动改成 `https://`，请记录这个现象与页面报错。不要因为本机显示 `local_ready` 就认为已绕过全部车机限制，也不要在 HTTPS 地址后继续反复配对。

## 第四步：探测通过后再接画面

1. 保持车机网络探测开启，它负责兼容地址；打开 Browser Output，选择分辨率。
2. 完整停止后重新 Start CarPlay，让发送 iPhone 接入，确认接收机有原生 CarPlay 画面。
3. 关闭电脑上的播放页，避免占用唯一观看／控制连接。
4. 在车机探测页点 **打开 CarPlay 播放页**，或访问 **`http://99.99.99.99:8080/`**。
5. 输入 Display 中的四位配对码（前导零需要保留）。
6. 依次测试：连续画面、点击 App、单指拖图、长按松手、刷新恢复。首版仍是单指触摸。

80 / 8081 是探测页；8080 是 CarPlay 播放页。这两类服务相互独立。探测通过但播放页打不开时，检查 Browser Output 是否在新的 CarPlay 会话中生效。

## 失败时发送什么

在接收机 Settings → Display 点击 **Copy Network Status / 复制探测状态**，把文字发回来，同时说明：

- 电脑上三个地址各自能否打开。
- 车机 80 和 8081 两个地址各自的结果。
- 地址栏最后显示 HTTP 还是 HTTPS，以及报错文字。

日志：`/var/mobile/Library/Showcase/logs/network-probe.log`。
状态 JSON：`/var/mobile/Library/Showcase/network-probe.json`。
这两个文件不包含配对码；仍不要分享 `browser-token`。

| 状态 | 含义与处理 |
| --- | --- |
| `waiting_hotspot` | 没找到有效热点 IPv4 桥；开启个人热点并让一台设备连接，再刷新 |
| `ambiguous_hotspot` | 检测到多个候选桥网段，为避免改错接口未配置地址；发送状态和日志 |
| `address_conflict` | 99.99.99.99 已存在，本工具不接管它；检查其他投屏／VPN 工具及此前残留 |
| `add_failed` | iOS 拒绝地址配置，例如权限不足；检查 Dopamine 状态、安装签名及日志里的 errno |
| `verify_failed` | 别名、原热点地址或本地路由未通过检查，已尝试回滚；发送日志 |
| `retry_required` | 连续／累计异常达到保护阈值，已停止配置重试；先看日志，再关闭并开启探测 |
| `cleanup_failed` | 无法确认临时地址已清理；停止测试、保留日志，必要时重启手机后重新越狱 |
| `local_ready` 但电脑打不开兼容地址 | 本机检查通过但热点到别名的实际投递未通过；发送结果与日志 |
| 电脑可开兼容地址、车机打不开 | 仍可能有车机地址／HTTP 策略限制；保留具体错误，下一步评估域名／HTTPS |

## 关闭与恢复

关闭车机网络探测后等约 2 秒、刷新状态，兼容探测入口应停止响应；普通 CarPlay 可继续运行。
本工具只增删自己在回环接口创建的 `/32` 地址，由内核增删相应本地路由；热点主地址用于检测与回程检查，不替换热点主地址、DHCP、默认路由，不清空系统防火墙规则。

独立清理进程在探测主进程退出或被单独 SIGKILL 时撤销自有地址；若整个进程组被硬杀或系统同时结束两个进程，则不能保证即时清理。
遇到残留冲突或清理失败，可重启手机清除临时内核网络状态，再通过 Dopamine 重新越狱；不要随意删除其他应用的地址／路由。

## 自动化验证范围

- 生产网络状态机的模拟后端：原主地址保持、没有热点、多个候选、已有地址保护、权限错误、路由验证失败回滚、接口重建、外部修改保护、失败阈值、普通退出及控制进程 SIGKILL 后的清理。
- 真实 Darwin PF_ROUTE v5 只读查询，验证结构布局及本机回环路由判断；Mac 构建的地址修改代码被禁用。
- 真实探测 HTTP 服务及隔离 Chrome：持续响应、Host 校验、HTTP 上收到 TLS 的诊断、单实例锁及停止清理。
- 原有 1080p MSE、四位配对、视频重连和单指输入回归。
- iOS arm64 编译、签名与 Debian 包内容校验。

这些验证不能代替接收机和特斯拉的实际内核／网络测试。
