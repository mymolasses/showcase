# Showcase+ 1.7.2 / 1020：浏览器输出与分辨率

仅保留：H.264 → 同源 WSS → Worker → WebCodecs → OffscreenCanvas / WebGL2。
网页不再提供 JPEG、MJPEG、软件解码、WebRTC 或旧模式选择器，也不会回退到它们。
手机端直接转发压缩 H.264，不为浏览器解码、缩放或重编码图片。音频继续由发送 iPhone 通过汽车蓝牙播放。

## 必要条件

- 车机需要浏览器信任的 HTTPS 证书与同源 WSS。
- 个人激活包自动配置 car.littlepond.eu.org 并检查可信证书更新；普通构建保留手动域名与 P12 导入。热点路由保留；HTTP 入口仅适合网络诊断。
- 浏览器需要 Worker 中的 VideoDecoder、OffscreenCanvas、WebGL2 和支持源 AVC Profile 的解码器。
- 不满足条件时明确显示失败原因；不尝试低帧率后备。localhost 的 HTTP 例外只用于本机开发，不能代表车机的局域网 HTTP 可用。

## 保留功能

输出比例可自动适配浏览器，也可选择手机比例或固定分辨率。修改源尺寸会重新连接 CarPlay。
网页“菜单 → 输出比例”与手机“显示 → 输出比例”新增：

- **自定义宽高**：填写宽、高后点击应用；输入过程中不会重连。宽高须为 240–4096 的偶数，总像素不超过 8294400，宽高比 0.4–4。已移除旧的 1080 高度限制。设置保存在接收机，网页刷新或 App 重开仍保留。
- **自动左右分列 · 最大高度**：测量浏览器可用区域及像素密度，在不超过窗口可用高度、满足所填比例约束的前提下取最大高度。比例正数自由填写，不设置固定输入上下限，应用时四舍五入并显示两位小数，默认 1.45。降低比例增加允许的高度，提高比例给左右排列留更多余量。例如 1600×1250 的窗口在 1.45 时输出 1600×1102，在 1.30 时输出 1600×1230，在 1.20 时直接使用窗口比例输出 1600×1250，在 2.50 时输出 1600×640。更低的比例不会突破浏览器可用区域的高度。全屏和窗口变化会重新计算，尺寸抖动不会连续重连。

自动模式保留 1920 的输出宽度预算；自定义可使用更高宽度。手机原有默认分辨率预算不变。自动左右分列不是识别画面内容或自动探测苹果的布局断点：网页无法读取发送机内部 Dashboard 视图尺寸，也无法知道当前卡片是否左右排列。手机和网页均提示 **1.30 是已知内部布局切换参考阈值：内部区域宽高比大于 1.30 时左右排列，小于或等于时上下排列**。这不是整个视频输出比例的固定阈值，也不保证所有 iOS 版本沿用。默认 1.45 为 Dock 等占用预留经验余量，允许自由调低测试。零、负数、非有限值，以及舍入两位后为零的输入无效；输出仍受像素尺寸和设备能力限制，不能生成有效尺寸时会明确提示。若窗口比左右布局允许的比例更高，无裁切、无变形和无黑边不能同时实现，此时保留上下黑边。实际源尺寸始终以发送端返回的配置为准。

浏览器提示与诊断给出 CSS 可用区域、采样像素密度、像素尺寸、输出目标及所选比例。它们不是 Tesla 整块屏幕或浏览器解码能力的固定上限。更高分辨率会增加发送端和接收端负担，具体可用值由设备与浏览器决定。

完整/铺满保持等比映射；单指触摸、长按、拖动、失焦取消和手机/网页输入交接保留。
静态画面不算卡顿；断线保留最后一帧，连接恢复后等待 IDR。普通重连与前后台切换复用 Worker 和图形上下文，重建 WebSocket 和解码器；连接代次会隔离旧回调。离开页面时释放 Worker。

## 延迟和诊断

网络接收、解析、解码和 WebGL 绘制全部在 Worker，主线程仅处理界面和触摸。
解码使用 optimizeForLatency。允许短时网络突发；待解码输入达到 24 个，或至少四个尚未被解码器接收的请求持续积压超过 250ms 时，重置参考链并等待 IDR；不随意丢弃参考帧后继续解码。
服务端队列最多八个待发包，仍完整发送已开始写出的 WS 帧，避免截断协议。
WebGL 保留绘图缓冲以支持静态导航和断线期间的最后一帧，主线程不读取或复制 GPU 画布。实现保留本项目的 AVCC 配置及消息封装，没有复制第三方播放器代码。

诊断中的 inputFrames、drawnFrames、decodeQueue、droppedFrames、recoveries、lastDrawAgeMs 区分传输、解码和绘制。
帧率仅由实际 WebGL 绘制增加，定时器和 WebSocket connected 状态不计为成功出图。

## 验证范围

真实 Chrome 覆盖 Baseline/Main/High H.264、可信 HTTPS/WSS、真实像素及上下方向、触摸、静态画面、断线重连和分辨率切换。
CI 的独立浏览器作业以 1080p/30fps 源检查 GPU 像素；macOS 原生集成以 10fps 全分辨率源检查实际服务的转发、解码、触摸及生命周期，避开 Intel 无头 GPU 的同步读回问题。两项均为功能验证，不是车机性能基准。
独立回归覆盖解码积压恢复、旧代回调清理及能力失败提示。浏览器验证不能代替 iPhone 原生编译、热点及目标车机实测。
这次改造未新增 VPN，也没有证明各款车机在 D 挡下的表现；该效果仍需目标硬件验收。
